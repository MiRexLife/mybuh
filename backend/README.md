# sber-sync-backend

Небольшой сервер, который забирает выписку по счёту ИП из Sber API (СберБизнес) и
отдаёт её как простой JSON — чтобы фронтенд-инструмент учёта УСН 6% мог подтягивать
операции сам, без ручной выгрузки CSV.

## Почему это отдельный сервер, а не часть браузерного инструмента

Sber API требует client_id/client_secret и OAuth-токен, привязанный к вашей
организации. Эти секреты нельзя хранить в коде, который выполняется в браузере —
их увидит любой, кто откроет страницу. Поэтому секреты живут здесь, на сервере,
который контролируете только вы.

## Что нужно сделать один раз

1. **Зарегистрировать приложение.** Зайдите на developers.sber.ru, создайте
   приложение для сервиса «Выписки по счёту» (RKO / statement). Вам выдадут:
   - `client_id` и `client_secret`
   - точные адреса авторизации и API (тестовый и промышленный контур — это разные хосты,
     их нужно взять из личного кабинета, не угадывать)
   - список разрешённых `redirect_uri`

2. **Установить зависимости:**
   ```
   npm install
   ```

3. **Заполнить `.env`** (скопируйте `.env.example` → `.env`):
   - `SBER_CLIENT_ID`, `SBER_CLIENT_SECRET` — из личного кабинета
   - `SBER_REDIRECT_URI` — например `http://localhost:3000/oauth/callback` для локального
     теста, или ваш реальный домен в проде (должен совпадать с тем, что указали при
     регистрации приложения)
   - `SBER_AUTH_BASE_URL`, `SBER_API_BASE_URL` — тоже из личного кабинета
   - `SBER_ACCOUNT_NUMBER` — номер расчётного счёта ИП
   - `LOCAL_API_KEY` — придумайте случайную строку (`openssl rand -hex 32`),
     ей фронтенд будет представляться этому серверу

4. **Запустить сервер:**
   ```
   npm start
   ```

5. **Один раз авторизоваться.** Откройте в браузере `http://localhost:3000/auth`,
   войдите через СберБизнес ID, разрешите доступ. После этого токены сохранятся
   в `data/tokens.json` и будут обновляться автоматически.

6. **Проверить синхронизацию вручную:**
   ```
   npm run sync-now
   ```
   Или через API: `POST /api/sync-now` с заголовком
   `Authorization: Bearer <LOCAL_API_KEY>`.

После этого сервер сам подтягивает выписку каждый день в 07:00 и хранит
операции в `data/transactions.json`.

## Как фронтенд-инструмент получает данные

Фронтенд делает запрос:
```
GET https://ваш-сервер/api/transactions?since=2026-01-01
Authorization: Bearer <LOCAL_API_KEY>
```
и получает `{ transactions: [...] }` — только поступления, уже без исходящих операций.
Дальше инструмент сам решает, что из этого добавить в свой список (сверяя по id,
чтобы не задублировать вручную занесённые операции).

## Важно перед тем, как использовать в реальной работе

- **Поля ответа API уточните сами.** В `sberClient.js` и `txStore.js` оставлены
  комментарии `TODO` в местах, где я предположил названия полей (`amount`, `direction`,
  список операций). Точную структуру ответа дайте свериться с реальным JSON, который
  вернёт API после вашей авторизации — тестового контура нет под рукой, чтобы
  проверить byte-in-byte.
- **client_secret нужно обновлять** — по данным банка, примерно раз в 40 дней
  через отдельный запрос. Это не автоматизировано в коде, добавьте по инструкции
  из личного кабинета.
- **Не выкладывайте `.env` и папку `data/` в публичный репозиторий** — там токены
  и секреты. `.gitignore` уже их исключает.
- Держите этот сервер там, куда у вас есть контроль (свой VPS, облако) —
  не на бесплатном общем хостинге без HTTPS.
